## 2. Known problems in the demo (we must avoid these)

| # | Problem | Where | AICC102 fix |
|---|---|---|---|
| P1 | **No YAML frontmatter.** The file starts with `description: …` without `---` fences, so the whole line becomes the description (the skill list shows `description: Run documentation…`). | `commands/run-quality-check.md` | Every skill and agent file starts with valid `---` frontmatter. |
| P2 | **Conflicts with `docstring-writer`.** The command asks it to document **JavaScript/TypeScript**, but the agent is defined for **C# XML comments only**. Running the two agents in parallel also lets both edit files at the same time. | `run-quality-check.md` and `docstring-writer.md` | No such command. Reviewers are read-only, and only the main session edits files. |
| P3 | **No path scoping on rules.** All 5 rules load on every task, whether it is frontend, backend or test work. | `.claude/rules/*.md` | `paths:` frontmatter on every rule. |
| P4 | **Rules are vague and overlap.** "Where appropriate" and "where practical" make them impossible to check. Thin controllers, no stack traces and no secrets are each repeated in 2–3 files. | `rules/*` | One owner per rule, worded so it can be checked, and linked to the FR, VR and NFR IDs. |
| P5 | **The frontend is JavaScript, not TypeScript.** `.jsx`/`.js` files, `api/client.js`, `App.test.jsx`. | Demo `frontend/` | Vite React-**TS** template, `strict` mode, typed DTOs. |
| P6 | **Agents have no `tools:` limit.** "Reviewers" and the testing agent can Edit and Write even though their instructions say not to change production code. | `agents/*.md` | `tools:` allow-lists, with read-only reviewers. |
| P7 | **Malformed agent name.** The frontmatter has trailing whitespace (`name: react-standards-reviewer␠␠`). The agent registers with a trailing space (`react-standards-reviewer `). | `agents/react-standards-reviewer.md` | Lint the frontmatter and remove trailing whitespace. |
| P8 | **Hard-coded to the Expense Tracker.** Domain wording appears in the agents, `session-start.cs` and the hook messages ("protects Expense Tracker tables"). | Agents, hooks | Generic wording, with project facts kept only in CLAUDE.md. |
| P9 | **A slow hook runtime.** Every Bash call runs `dotnet run file.cs` (a file-based app compile, 15 s timeout). The code also uses `var`, which our NFR-04 forbids. | `hooks/pre-tool-use.cs` | Measure it first. If it's too slow, use a lighter script runner or a prebuilt binary. The code uses explicit types. |
| P10 | **The pre-hook only watches Bash.** Nothing stops Edit or Write from changing secrets, DB files or migrations. | `settings.json` | Add an `Edit\|Write` matcher (see the pre-hook row above). |
| P11 | **Design conflicts with AICC102.** Errors are `{error: "…"}`, not ProblemDetails. Aggregation happens **on the client**. Categories are a **fixed list**. Dates are stored as strings. There is no paging, sorting or searching on the server. | Demo `CLAUDE.md` and architecture | Requirements FR-09, FR-13–FR-16 and VR-01–VR-12 apply. |
| P12 | **Out-of-scope content.** The AI Assistant sidecar (`ANTHROPIC_API_KEY`) and the `MonthlyBudget` entity. | Demo `CLAUDE.md` | Not carried over. |
| P13 | **Gaps in git hygiene.** `.claude/settings.local.json` and `.claude/model-switch.log` aren't git-ignored. | Demo `.gitignore` | AICC102 `.gitignore` covers both (NFR-02). |
| P14 | **An unpinned MCP package.** `npx -y mcp-sqlite` always fetches the latest version. | `.mcp.json` | Pin the version. |
| P15 | **CLAUDE.md is too long and drifts.** About 14.6 KB of architecture narrative, with `Program.cs` described twice. | Demo `CLAUDE.md` | A short CLAUDE.md that links to the docs. |
