# AICC102 — Expense Management API: Architecture

This is a **design document**; nothing here exists yet. Sources: `requirements.md` (FR/VR/BR/NFR IDs), `reuse-assessment.md` and `plugin-evaluation.md`. Conflicts are listed in §8.

## 1. Layers

```
 React + TS client (Vite) ── frontend/src/api/* is the ONLY place that calls fetch
        │  JSON over HTTP  ·  errors arrive as application/problem+json
        ▼
 Controllers ─────── HTTP only: bind Contracts, call a service, map ServiceResult<T> → HTTP
        ▼
 Services ─────────── business rules (VR/BR), validation, budget checks → ServiceResult<T>
        ▼
 AppDbContext ─────── EF Core: entity config (Fluent API), queries, SaveChangesAsync
        ▼
 SQLite ───────────── expenses.db (local dev, git-ignored) · tests use in-memory SQLite (§6)
```

| Concern | Where it lives |
|---|---|
| Request/response contracts (DTOs) | `Contracts/`: records, never EF entities |
| Domain entities and enums | `Domain/`: no HTTP or EF attributes |
| Shape errors (bad JSON, wrong types) | `[ApiController]` automatic 400 `ValidationProblemDetails` |
| Business validation (VR-01…VR-12) | `Services/Validation/*`: pure static validators, unit-tested |
| Business rules (BR-01…BR-08) | `Services/*Service.cs` and `Services/BudgetCalculator.cs` |
| ServiceResult → HTTP mapping | `Infrastructure/ServiceResultMapper.cs` (used by controllers) |
| Unhandled exceptions → 500 | `AddProblemDetails()` + `UseExceptionHandler()` with no stack trace and a `traceId` |

## 3. Entities and relationships

```
Category 1 ──< Expense        (FK CategoryId, OnDelete Restrict)
Category 1 ──< Budget         (FK CategoryId, OnDelete Restrict; unique (CategoryId, Year, Month))
```

| Entity | Fields (C# type) | Constraints |
|---|---|---|
| `Category` | `int Id`, `string Name`, `string? Description` | Name 1–50 chars trimmed, unique case-insensitive (`COLLATE NOCASE` index). Description ≤ 250 |
| `Expense` | `int Id`, `string Title`, `decimal Amount`, `DateOnly Date`, `int CategoryId`, `string? Notes`, `DateTime CreatedAt` | Title 1–100. 0 < Amount ≤ 1,000,000 with ≤ 2 dp. Date required, ≤ today (UTC). Notes ≤ 500. Index on `Date` and `CategoryId` |
| `Budget` | `int Id`, `int CategoryId`, `int Year`, `int Month`, `decimal LimitAmount`, `BudgetEnforcement Enforcement` | LimitAmount > 0 with ≤ 2 dp. Month 1–12. One per (CategoryId, Year, Month): duplicates → 409 |

`BudgetEnforcement { Hard, Soft }` and `BudgetStatus { OnTrack, Warning, Exceeded }` are stored as strings. Money uses `decimal(18,2)`.
**Category delete (BR-06):** if the category has expenses → 409. Otherwise the service deletes its budgets and then the category, in one `SaveChangesAsync`. This works with `Restrict`.
**Monthly spending:** `spent` = sum of `Amount` for the category's expenses where `Date` is in [first day, last day] of (Year, Month).
**Status (BR-01):** `pct = spent / LimitAmount × 100` (decimal). `< 80` OnTrack, `80–100` Warning, `> 100` Exceeded.
**Enforcement on create/update (BR-02…04):** `projected = spent − (old amount if same category+month) + new amount`. If `Hard` and `projected > LimitAmount` → **422**, nothing saved. If `Soft` → saved, plus a warning when the status moves to `Warning` or becomes `Exceeded`. An update checks the *target* category and month.

## 4. REST API inventory (planned)

Base URL `/api`. JSON uses camelCase. Every error is `application/problem+json`. 400 = `ValidationProblemDetails` with `errors`.

| Method | Route | Purpose / query | Success | Errors |
|---|---|---|---|---|
| GET | `/api/categories` | List, sorted by name | 200 | — |
| GET | `/api/categories/{id}` | Get one | 200 | 404 |
| POST | `/api/categories` | Create | 201 + Location | 400, 409 duplicate name |
| PUT | `/api/categories/{id}` | Update | 200 | 400, 404, 409 duplicate name |
| DELETE | `/api/categories/{id}` | Delete (removes its budgets) | 204 | 404, 409 has expenses |
| GET | `/api/expenses` | `q, categoryId, from, to, minAmount, maxAmount, sortBy=date\|amount\|title, sortDir=asc\|desc, page≥1, pageSize 1–100` | 200 `PagedResponse<ExpenseResponse>` | 400 (VR-10…12) |
| GET | `/api/expenses/{id}` | Get one | 200 | 404 |
| POST | `/api/expenses` | Create, with budget check | 201 + Location, body has `warnings[]` | 400 (incl. unknown `categoryId`), **422 hard budget** |
| PUT | `/api/expenses/{id}` | Update, with budget check | 200, body has `warnings[]` | 400, 404, **422 hard budget** |
| DELETE | `/api/expenses/{id}` | Delete | 204 | 404 |
| GET | `/api/budgets?month=YYYY-MM` | List (optional month filter), each with `spent, remaining, percentUsed, status` | 200 | 400 bad month |
| GET | `/api/budgets/{id}` | Get one with calculated status | 200 | 404 |
| POST | `/api/budgets` | Create | 201 + Location | 400, 409 duplicate (category, month) |
| PUT | `/api/budgets/{id}` | Update limit, enforcement, period | 200 | 400, 404, 409 |
| DELETE | `/api/budgets/{id}` | Delete | 204 | 404 |
| GET | `/api/summaries/monthly?year=` | Totals and counts per month | 200 | 400 |
| GET | `/api/summaries/categories?month=YYYY-MM` | Per-category total, count, budget %, status | 200 | 400 |
| GET | `/api/reports/monthly?month=&format=json\|csv` | JSON report or CSV download (`text/csv`, attachment) | 200 | 400 bad month or format |
| GET | `/openapi/v1.json` | OpenAPI document (Development only) | 200 | — |

The 422 body is ProblemDetails with extensions `categoryId, month, limit, currentSpent, attemptedAmount`.
A soft warning looks like: `201 { …expense, "warnings": ["Budget exceeded for 'Food' in 2026-10: 1,050.00 / 1,000.00"] }`.

## 5. SQLite `decimal` limitation

SQLite has no decimal type, so EF Core stores `decimal` as TEXT. The SQLite provider **cannot translate `ORDER BY` on decimal columns or `Sum/Average/Min/Max` over decimals**. These throw at runtime instead of silently giving wrong answers. TEXT ordering would be lexical in any case ("100" < "9"). Decimal comparisons in `WHERE` may be translatable, but this must be confirmed by an EF Core 10 test before we rely on it.

**Decision:**
1. Apply the supported filters in SQL first: `categoryId`, date range, `q` (`LIKE`), plus the amount range if the test confirms it.
2. Materialize only that filtered set with `AsNoTracking()`, projected to the needed columns.
3. Sort and aggregate in C# using `decimal`: `OrderBy(e => e.Amount)`, `Sum(e => e.Amount)`.
4. Paging: when `sortBy` is `date` or `title`, page **in SQL** (`Skip/Take`). When `sortBy=amount`, sort the filtered set in memory and then page. Summaries and reports are always limited to one month or year.
5. **Never** convert money to `double`/`float` (no value converters to REAL, no casts).

This is acceptable because the app is local and single-user with a bounded dataset (NFR-07 targets 10k expenses; a filtered set of 10k rows is a few hundred KB). Storing integer cents was considered and rejected: the requirements set `decimal Amount`.

## 6. Testing strategy

| Layer | Tooling | Covers |
|---|---|---|
| Unit | xUnit | Validators (VR-01…12 boundaries: 0, 0.01, 1,000,000, 1,000,000.01, 10.123, today/tomorrow, 100/101 chars), `BudgetCalculator` (79.99/80/100/100.01 %), hard/soft decisions, summary math, CSV escaping |
| Integration | xUnit + `WebApplicationFactory<Program>` | Every FR AC: CRUD, status codes, ProblemDetails shape, 409/422, warnings, filter/sort/paging, JSON and CSV export |
| Frontend | Vitest + React Testing Library | `api/client.ts` ProblemDetails → `ApiError`, form field errors, 422 vs. soft-warning display |

**Database isolation:**
- `TestApiFactory` removes the app's `DbContextOptions<AppDbContext>` registration. It registers a dedicated `SqliteConnection("DataSource=:memory:")` that stays open for the factory's lifetime, and applies the migrations to it.
- Each test class gets its own factory and connection and seeds its own data. Nothing is shared between test classes.
- The factory runs in the `Testing` environment. The API **never migrates at startup** (FR-17: `dotnet ef database update` creates the dev DB). A guard fails the test run if the connection string isn't `:memory:`, so tests can't touch `expenses.db`.
- "Today" comes from an injected `TimeProvider`. Tests substitute a fixed clock written by hand (no extra package).

## 7. Decisions and constraints

| # | Decision |
|---|---|
| D1 | Controllers stay thin: no `AppDbContext`, no business rules, no `if` chains over rules. |
| D2 | Business rules live only in services. Validators and `BudgetCalculator` are pure and side-effect free. |
| D3 | Services return `ServiceResult<T>`. Mapping to HTTP status lives only in `ServiceResultMapper`. |
| D4 | TypeScript `strict`. All HTTP goes through `frontend/src/api/`, and ProblemDetails is mapped to typed errors there. |
| D5 | No authentication, multi-user support or currencies (requirements §7). |
| D6 | Schema changes happen only through EF Core migrations. No `EnsureCreated` outside tests. |
| D7 | No secrets in git. `*.db`, `.env*` and `settings.local.json` are ignored (NFR-02). |
| D8 | Explicit C# types (no `var`), nullable enabled, `CancellationToken` on all async methods (NFR-04/05). |
| D9 | The mandatory Claude Code features follow requirements §8. Cognine React plugin for the client; no Cognine .NET plugin (plugin-evaluation). |

```csharp
public enum ServiceStatus { Ok, Created, NoContent, ValidationFailed, NotFound, Conflict, BudgetRejected }

public sealed record ServiceResult<T>(
    ServiceStatus Status,
    T? Value,
    IReadOnlyList<string> Warnings,
    IReadOnlyDictionary<string, string[]>? Errors,
    string? Detail);

// Controller: HTTP only
[HttpPost]
public async Task<IActionResult> Create(CreateExpenseRequest request, CancellationToken ct)
{
    ServiceResult<ExpenseResponse> result = await _expenseService.CreateAsync(request, ct);
    return ServiceResultMapper.ToActionResult(this, result, nameof(GetById));
}
```
